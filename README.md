# NEON / PC — магазин сборок

MVP магазина для прямых заявок ИП. FastAPI, SQLite, SQLAlchemy, Jinja2, HTML/CSS/Vanilla JS.

## Запуск в Windows PowerShell

Из корня проекта:

```powershell
cd E:\code\Codex\Pc_project
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe setup_env.py
.\.venv\Scripts\python.exe seed.py
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

При первом запуске setup_env.py введите демо-логин и пароль, заданные в ТЗ. Данные сохраняются только в .env. В подготовленном экземпляре окружение и база уже созданы; достаточно последней команды. Скрипт не перезаписывает существующий .env. Если окружение активировано, эквивалент запуска — `uvicorn backend.main:app --reload`.

Витрина: http://127.0.0.1:8000/
Конфигуратор: http://127.0.0.1:8000/configurator
Политика конфиденциальности: http://127.0.0.1:8000/privacy
Админка: http://127.0.0.1:8000/admin

Фото задаются HTTPS-ссылками. Если фото нет, выводится локальная CSS-иллюстрация. В формах админки характеристики — JSON-объект, состав сборки — JSON-массив ID компонентов. Добавление, редактирование и удаление доступны в /admin. Компоненты, включённые в готовую сборку, защищены от удаления.

## Витрина: реквизиты, контакты и документы

Всё, что отличается от клиента к клиенту, задаётся в `.env` и подставляется в шаблоны:

| Переменная | Куда попадает |
|---|---|
| `SELLER_LEGAL_NAME`, `SELLER_INN`, `SELLER_OGRN`, `SELLER_ADDRESS` | политика конфиденциальности и строка реквизитов в подвале |
| `SELLER_PHONE`, `SELLER_EMAIL`, `SELLER_TELEGRAM`, `SELLER_HOURS` | блок «Контакты» на главной |
| `SITE_DELIVERY`, `SITE_PAYMENT`, `SITE_WARRANTY` | блок «Доставка, оплата и гарантия» |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о новых заявках в Telegram |

Пока контакты пустые, блок на главной честно пишет, что они появятся после запуска продаж — никаких выдуманных телефонов. Форма заявки требует галочку согласия на обработку персональных данных; без неё сервер возвращает 400 и заявка не создаётся. Согласие сохраняется в заявке вместе с датой и ссылкой на политику.

Уведомления в Telegram необязательны: без них заявки просто лежат в админке. Ошибка отправки пишется в лог и не ломает оформление.


## Структура

- backend/main.py — маршруты, авторизация, формы админки, заказы.
- backend/site.py — реквизиты, контакты и тексты блоков из `.env`.
- backend/notify.py — уведомление менеджера о заявке в Telegram.
- backend/models.py — пять моделей SQLAlchemy.
- backend/catalog.py — совместимость, цены, снимок состава.
- backend/security.py — хеширование паролей и CSRF.
- backend/database.py — подключение к SQLite.
- templates/ — Jinja2-страницы.
- static/ — CSS и JavaScript.
- seed.py — идемпотентное заполнение БД.
- setup_env.py — создание локальной конфигурации с случайным ключом.
- tests/test_app.py — интеграционные проверки на отдельной базе.

## Поведение

Клиент может заказать готовую сборку или отправить частичную конфигурацию на согласование. Выбирается не более одного товара каждой категории. JS блокирует несовместимые сокеты CPU/платы и типы ОЗУ; сервер повторяет проверки. Это базовая проверка: BIOS, габариты, охлаждение, разъёмы и запас мощности проверяет менеджер.

Цена рассчитывается сервером с Decimal; клиент не может подменить итог. Заказ фиксирует названия и цены на момент оформления. Остатки атомарно уменьшаются при заявке; ошибка наличия откатывает всю транзакцию. Неоплаченные заявки тоже резервируют товар. Автоматическое снятие резерва и отмена не входят в MVP; администратор корректирует остаток вручную после сверки.

Статусы меняются последовательно: Новый → В работе → Выполнен. Seed добавляет 10 компонентов (включая DDR4 для отрицательного теста), 7 категорий и одну демонстрационную готовую сборку. Повторный seed не сбрасывает данные.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
```

Проверяются страницы (включая `/privacy` и favicon), доступ к админке, CSRF, обязательное согласие на обработку данных, создание заказов, несовместимость, подмена цены, откат остатков, CRUD, статусы и повторный seed.

## Перед публикацией

Это локальный MVP. Заполните `SELLER_*`, `SITE_DELIVERY`, `SITE_PAYMENT`, `SITE_WARRANTY` в `.env` — после этого витрина и политика перестанут быть демонстрационными. Политика в `/privacy` — рабочий черновик: перед публикацией её проверяет юрист, а уведомление о заявке в Telegram означает передачу имени и телефона в сторонний мессенджер (это прямо описано в политике).

Смените пароль администратора и SECRET_KEY, включите COOKIE_SECURE=true и HTTPS. В подготовленном `.env` стоит демо-пара `admin`/`admin` — это только для локального запуска. Смена ADMIN_PASSWORD в .env не обновляет существующий хеш: для первого запуска используйте новую базу, для действующего магазина требуется отдельная процедура смены пароля без удаления данных.

Внедрите ограничение частоты публичных заявок/антиспам, резервное копирование, мониторинг и политику освобождения резервов. Текущий лимит входа хранится в памяти одного процесса. Не запускайте --reload в production. Не публикуйте .env и store.db. Платёжного шлюза, доставки и уведомлений менеджеру в MVP нет.


## 3D-конфигуратор и новый интерфейс

Главная: `/`, готовые сборки: `/builds`, конфигуратор: `/configurator`.
Публичные страницы используют `templates/public.html` и `static/product.css` (Inter, тёмная палитра, фиолетовый акцент). Админка сохраняет отдельную компактную тему.

`static/sockets.js` содержит профиль креплений для иллюстративной ASUS B550-F GLB: CPU, DIMM A1/A2/B1/B2, PCIe и M.2. `attachPart` меняет родителя и задаёт локальные координаты. `static/assembly.js` нормализует исходные оси GLB и создаёт процедурные корпус/БП. Пока корпус не выбран, в конфигураторе стоит пустой корпус-витрина, чтобы сцена не выглядела чёрным прямоугольником. `static/pc-scene.js` управляет загрузкой, подсветкой, выбором DIMM и ракурсами. В конфигураторе нет автоматического вращения и анимаций появления; вращающееся превью есть только на главной.

Проверки: `python -m unittest discover -s tests -v`, `node test-sockets.mjs`, `node verify-models.mjs`. Браузерный сценарий: `node browser-check.mjs` при запущенном изолированном Chrome с CDP на 9225; проверяет маршруты, конфликт CPU/платы, совместимую сборку и мобильную ширину. Снимки сохраняются в logs/. Тест не оформляет реальные заказы.

Модели иллюстрируют категории товаров и не являются точными копиями каждого товара. Логическая проверка охватывает сокет и тип памяти. Реальные габариты, мощность, охлаждение, BIOS и условия продажи требуют дополнительной проверки. Авторы моделей и CC BY 4.0 перечислены на `/static/model-credits.html`. Загружать GitHub-файлы следует через `https://gh-proxy.com/`.
